# 《偷机》程序执行版策划案（Jam 版）

> 用途：给程序快速理解和落地，不替代原策划的细节设定。  
> 原案依据：《偷机_道具策划案》《偷机_数值策划案》《偷机_一周目关卡策划案》《偷机_音效策划案》。  
> 当前工程：`E:\Unreal\StealPhone`，UE 5.7，First Person Blueprint，Survival Horror 变体。

## 01｜一分钟理解

玩家是一个半夜想拿回手机的孩子。手机被妈妈藏在书房，玩家必须避开父亲、穿过昏暗的房子取回手机，再回到床上装睡。

这不是“打人”或“跑酷”游戏，而是**控制碰撞**的潜行游戏：

- 每一步、每次碰门、碰玩具车、拿放手机，都会发出材质对应的声音。
- 声音会消耗父亲睡眠的“鼾声耐久” H。
- 玩家不看数值，只通过父亲的鼾声判断危险。
- 第一次拿手机会固定触发父亲夜起；玩家必须放回手机并躲进衣帽间。
- 父亲重新熟睡后，第二次拿手机，安全返回卧室 C 回床，游戏完成。

## 02｜三条不可违背的红线

1. **碰撞是唯一风险来源。** 玩具车、手机和场景道具不能自己发声；看向、靠近、打开交互提示也不扣 H。
2. **正式游戏不显示 H、百分比、危险条。** 风险只通过三阶段鼾声、灯光、人物动作和声音反馈表达。
3. **尽量不出现文字。** 原策划中的目标文案只作为设计意图，不作为正式游戏 UI。

## 03｜核心循环

```text
观察环境 → 选择移动/交互 → 发生真实接触 → 播放材质碰撞反馈
→ 扣除鼾声耐久 H → 鼾声阶段变化 → 玩家调整节奏 → 等待恢复
```

玩家的核心决策不是“怎么打”，而是：

- 走哪条路线？
- 是否要碰开障碍？
- 现在是否值得冒一次碰撞风险？
- 什么时候停下来等鼾声恢复？
- 先放回手机还是先躲藏？

## 04｜P0 范围：Jam 必须完成

### 玩家与交互

- 第一人称移动、视角、脚步。
- 手部/足部当前材质状态。
- 摄像机射线交互：门、灯开关、窗帘、手机、袜子、床、躲藏区。
- 交互提示只用图标或物体高亮，不使用说明文字。

### 风险系统

- 材质系数表。
- 距离系数 D。
- H 扣除、恢复、三阶段鼾声。
- 同一碰撞去重与冷却。
- 父情节点的固定事件。

### 剧情流程

- 开场听妈妈藏手机。
- 关灯回卧室 C。
- 碰杯教学。
- 拉窗帘、推门、过道排障。
- 第一次拿手机、放回、躲藏。
- 父亲完整往返。
- 穿袜子、等待稳定鼾声。
- 第二次拿手机、返回卧室 C、回床结算。

### 必须准备的失败与重试

- H 归零：父亲被噪声惊醒。
- 第一次拿手机后未及时放回/躲藏：被父亲发现。
- 持手机躲藏或手机不在原位：检查点判负。
- 父亲往返期间提前暴露：判负。
- 成功、失败、暂停、重试状态完整复位。

### P0 先不做

- 父亲 3D 模型、自由搜索 AI。
- 复杂刚体连锁碰撞、物体持续滚动。
- 完整 7×8 材质矩阵的全部声音资源。
- 随机障碍、钥匙、封路、第二次夜起。
- 背包、存档、复杂动画和完整片头 CG。
- 现在就把项目改造成 C++ 工程。

## 05｜数值规则（程序按此实现）

### 单次风险

```text
L = C_player × C_object × D
H_after = clamp(H_before - L, 0, 100)
```

- H 初始为 100。
- 正式 UI 不显示 H。
- 只有“有效碰撞”才提交风险事件。
- 同一碰撞不能因为多层音效重复扣 H。

### 阶段

| H | 阶段 | 鼾声反馈 |
|---:|---|---|
| 67–100 | S1 熟睡 | 低沉、规律、连续 |
| 34–66 | S2 受扰 | 变轻、节奏不稳、短暂停顿 |
| 1–33 | S3 将醒 | 稀疏、断续、接近清醒 |
| 0 | 惊醒 | 鼾声停止，噪声失败 |

### 恢复

- 连续 2 秒没有新的风险碰撞后，H 以 6 点/秒恢复。
- 上限 100。
- 发生新碰撞时立即停止恢复，先处理本次扣除。
- 暂停时恢复计时同步暂停。

### 防重复

- 同一对玩家/物体在 0.25 秒内只保留一次事件。
- 同一对玩家/物体再次触发默认冷却 0.50 秒。
- 持续贴着或推着物体，不连续扣 H。
- 同一帧多个接触点合并为一次。
- 一次有效落脚只提交一次脚与当前地面的碰撞。
- 多个材质音效层只属于同一个 EventID。

### 特殊事件

- 第一次固定碰杯：播放陶瓷碰木地板声音，短暂演示 S2 鼾声；**不扣 H、不判负**。
- 第一次拿起手机：固定触发父亲夜起，与当前 H 无关；夜起期间暂停 H。
- 父亲回房、鼾声稳定约 3 秒后：H 重置为 100，开放第二次取机。
- 第二次拿起手机：正常计算一次碰撞，但**不重启父亲夜起**。

## 06｜材质系数

### 玩家接触材质

| 玩家材质 | 对应状态 | C_player | 优先级 |
|---|---|---:|---|
| 皮肤 | 赤手、赤脚 | 1.00 | P0 |
| 棉 | 棉袜、棉手套 | 0.75 | P0/P1 |
| 羊毛 | 厚羊毛袜 | 0.65 | P1 |
| 软布 | 软布鞋 | 0.90 | P1 |
| 橡胶 | 橡胶鞋 | 1.15 | P1 |
| 皮革 | 皮鞋、皮手套 | 1.30 / 1.10 | P1/P2 |
| 硬塑料 | 硬底塑料鞋 | 1.45 | P1 |

足部穿鞋时只读取鞋，袜子不与鞋相乘；手部和足部互不影响。

### 场景对象材质

| 对象材质 | C_object | 代表对象 | 优先级 |
|---|---:|---|---|
| 布料/软物 | 5 | 窗帘、衣物、被子、枕头、沙发 | P0 |
| 纸张/书本 | 12 | 书本、散落纸张 | P1 |
| 木材 | 35 | 门、桌、椅、床架、柜体 | P0 |
| 塑料 | 40 | 玩具车、垃圾桶、收纳盒、灯开关 | P0 |
| 玻璃/陶瓷 | 50 | 水杯、花瓶、手机硬质机身 | P0 |
| 金属 | 65 | 衣架、挂衣杆、金属桶 | P1 |
| 木地板 | 22 | 卧室、书房、衣帽间 | P0 |
| 瓷砖 | 28 | 客厅、餐厅、过道、卫生间 | P0 |

同一材质共用系数和同一音效组。玩具车和塑料垃圾桶可以共用 `SKIN_PLA` 等组合，不分别做一套声音。不得在同一次碰撞里再乘一次材质系数，也不得增加第四个风险乘数。

### 距离 D

| 声源到卧室 A 床边听音点 | D |
|---|---:|
| 3 米以内 | 1.00 |
| 3–6 米 | 0.80 |
| 6–10 米 | 0.60 |
| 10–15 米 | 0.40 |
| 15 米以上 | 0.20 |

**实现建议：P0 统一使用直线距离**，避免为每次碰撞做 NavMesh 寻路。原案写的是“灰盒阶段使用可通行路线距离”；如果坚持原案，就全项目统一使用寻路距离，不能两套混用。

## 07｜P0 场景与道具

| 区域 | 主要玩法 | P0 碰撞物 | 地面 |
|---|---|---|---|
| 客厅/餐厅 | 听妈妈藏手机、关灯 | 灯开关、沙发、桌椅 | 瓷砖 |
| 卧室 C | 碰杯教学、拉帘、推门、最终回床 | 水杯、窗帘、木门、床、床头柜 | 木地板 |
| 过道 | 观察并排开障碍 | 玩具车、塑料垃圾桶、木椅 | 瓷砖 |
| 书房 | 第一次取机、放回、第二次取机 | 书桌、办公椅、手机、书本 | 木地板 |
| 衣帽间 | 躲藏、穿袜子、听父亲往返 | 衣柜、衣物、棉袜 | 木地板 |
| 卧室 A | 父亲鼾声来源 | 只做声源，不做模型 | 木地板 |
| 卫生间 B | 父亲夜起目的地 | 只做门、水声和脚步 | 瓷砖 |

### 核心交互物

- 手机：固定在书桌，第一次拿取触发父亲事件；必须回原位放回。
- 水杯：固定碰杯教学，不扣 H。
- 木门：只有实际接触时发声，不单独播放开门音。
- 窗帘：手接触时播放布料声，并开启微光。
- 棉袜：衣帽间可见，穿上后下一次有效落脚开始切换足部材质。
- 藏身区：衣帽间内的宽松触发体积，不作为复杂物理躲藏。
- 床：只有持手机抵达卧室 C 床边时，才允许回床结算。

## 08｜程序结构建议

```text
BP_SP_PlayerCharacter
 ├─ BPC_SP_Interaction   摄像机射线、交互确认
 ├─ BPC_SP_Equipment     当前手部/足部材质
 └─ BPC_SP_Footstep      落脚检测、地面材质、脚步事件

BP_SP_RunManager         H、阶段、距离、冷却、统一风险入口
 ├─ BP_SP_FatherDirector 父亲固定时序，不负责 H 公式
 └─ 鼾声音频              S1/S2/S3，按阶段切换

场景交互物
 ├─ BPI_SP_Interactable  统一交互接口
 ├─ BP_SP_CollisionProp  可碰撞道具的通用材质与反馈
 └─ 专用 Actor           手机、水杯、门、窗帘、袜子、床、藏身区
```

### 关键原则

1. **所有风险都走 `BP_SP_RunManager` 的唯一入口。** 玩家、手机、门、水杯不能各自随手扣 H。
2. `BP_SP_RunManager` 负责把玩家材质、对象材质、声源位置转换成 `L` 和 `H_after`，然后广播阶段变化。
3. `BP_SP_FatherDirector` 只负责按时间播放父亲事件，不直接改 H；夜起期间由 RunManager 暂停 H。
4. 交互物通过接口暴露 `CanInteract`、`Interact`、`GetIcon`，不要在玩家里写大量类型判断。
5. 所有可调参数放到 DataTable/DataAsset，不把系数散落在蓝图节点里。
6. Debug 时允许在屏幕上显示 H；正式打包必须关闭。

## 09｜无文字表达方案

正式游戏只保留：暂停、设置、淡入淡出等必要界面。玩法提示优先使用：

- 手机屏幕反光/微亮，表示“目标在这里”。
- 物体描边或高亮，表示“可以交互”。
- 手部/足部图标，表示当前装备。
- 衣帽间灯光、衣架晃动、袜子高亮，表示躲藏和穿袜。
- 稳定鼾声 + 手机微光，表示安全窗口。
- 床铺高亮，表示最终回床点。
- 父亲的语音、脚步、门、水声承担剧情信息，不强制显示字幕。

原策划中的“去书房找到手机”“爸爸醒了！把手机放回去”等目标文案，只作为开发时的流程说明，不要直接搬到正式 HUD。

## 10｜碰撞质感的最低要求

碰撞质感不等于“碰撞时播放一个音效”。P0 每个核心碰撞至少有三层反馈：

1. **声音层**：材质组合正确，声音与实际接触同步；轻/重接触可用音量、音高和样本变化区分。
2. **物体层**：水杯掉落、玩具车轻晃/短距离位移、垃圾桶倾斜回弹、门轻颤、窗帘摆动。P0 用 Timeline/简单动画，不做复杂刚体连锁。
3. **玩家层**：手部/足部接触动作，必要时加非常轻微的镜头下沉或手部回弹；不要做强烈震屏。

**重要：这些表现层反馈不改变 H 的三项公式。** 视觉冲击和物理反馈可以随接触速度变化，但 H 仍然只由 `C_player × C_object × D` 决定，避免出现第四项隐藏系数。

## 11｜验收清单

- [ ] 玩家不动、只持续贴着物体时，不会持续扣 H。
- [ ] 一次有效落脚只扣一次；同一次碰撞不会因多层音效重复扣 H。
- [ ] 固定碰杯不扣 H，只演示 S2 鼾声后恢复。
- [ ] 第一次拿手机必触发父亲夜起；第二次拿手机不重启夜起。
- [ ] S1/S2/S3 仅凭鼾声可区分，正式 UI 没有 H 数值或危险条。
- [ ] 穿棉袜后返程脚步明显变轻；棉袜和鞋不同时叠乘。
- [ ] 父亲完整往返约 23–26 秒；回房后稳定约 3 秒才开放第二次取机。
- [ ] 未放回手机、持机躲藏、未躲藏、提前暴露均能稳定判负。
- [ ] 持手机回到卧室 C 并回床才触发成功。
- [ ] 关闭所有文字后，仍能靠声音、灯光、图标和物体高亮完成一周目。
- [ ] 成功路线和两类失败路线各连续跑 3 次，无卡死、漏音、重复扣 H 或状态错乱。

## 12｜建议制作顺序

1. **先做能走的灰盒**：自定义关卡、第一人称移动、门洞、房间、地面材质。
2. **做一个可验证的碰撞闭环**：脚步 + 一个塑料玩具车 + 一个木门 + H 扣除 + 鼾声阶段。
3. **接入统一 RunManager**：DataTable、恢复、去重、调试 HUD。
4. **做剧情主链**：第一次手机 → 父亲时序 → 放回 → 躲藏 → 稳定鼾声 → 第二次手机 → 回床。
5. **最后加质感**：杯子、物体晃动、手部动作、音效变体、无文字提示和整体混音。

先保证一条完整路线能通关，再增加材质种类和表现细节。
